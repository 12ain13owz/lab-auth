Feature

F2 · Login & session

API

POST/api/auth/login
{ "email", "password" }
→ 200 { data: { accessToken, expiresIn, user } }
       + Set-Cookie __Secure-refresh_token
→ 200 { data: { mfaRequired: true, mfaToken } }  // F6
→ 401 { code: "INVALID_CREDENTIALS" }
→ 403 { code: "EMAIL_NOT_VERIFIED" }  // only after a correct password
→ 429 + Retry-After

Backend stores

  • sessions: one row per login (= refresh family) with user_agent, ip, absolute_expires_at
  • refresh_tokens: token_hash, session_id, expires_at
  • users.last_login_at, reset failed counter
  • audit_log: login.succeeded / login.failed (email hash, ip)

Security

  • Unknown email and wrong password return the same body and similar timing (verify a dummy hash when the user is missing).
  • Throttle per account + per IP O7; prefer a cool-down over hard lock (lock = DoS on someone else's account).
  • autocomplete="username" / current-password so password managers work.
  • Access token kept in memory only, never in storage.
  • "session-expired" state comes from a failed refresh; carry returnUrl as a same-origin path only (open-redirect check).
