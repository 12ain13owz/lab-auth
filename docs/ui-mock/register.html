Feature

F1 · Register & verify

API

POST/api/auth/register
{ "email", "password", "displayName" }
→ 202 { message, timestamp }
→ 400 validation (field errors)
→ 429 rate limited

Backend stores

  • users: email (lower-cased), password_hash, display_name, status = pending
  • email_otps: code_hash, purpose = verify_email, expires_at, attempts
  • audit_log: register.requested

Security

  • Response is 202 for both new and existing emails; for an existing one, email a "someone tried to sign up" notice instead (see emails).
  • Password: min 12 and max 64+ characters, no composition rules, check against a breached-password list (HIBP k-anonymity).
  • Unknown body fields → 400.
  • Hash with argon2id O2
