Proposal for Step 2 · PostgreSQL

What the backend stores

Derived from the screens. Each table lists the feature that introduces it, so every migration lands with its slice. Secrets are hashed when they only need comparing, and encrypted when they must be read back.

Rules for every secret

ValueStored asWhy
Passwordargon2idSlow, memory-hard; low-entropy input (O2)
Refresh / reset tokenSHA-256≥ 256-bit random input, so a fast hash is enough
Email OTP, recovery codeHMAC-SHA256 (server key)Low entropy: plain SHA-256 of 6 digits is brute-forced instantly if the DB leaks
TOTP secretAES-256-GCMMust be read back to verify codes
