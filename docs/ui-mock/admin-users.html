Feature

F7 · RBAC & audit

API (role = admin)

GET/api/admin/users?q=&cursor=
PATCH/api/admin/users/{id}
POST/api/admin/users/{id}/revoke-sessions
GET/api/admin/audit?event=&userId=&cursor=
PATCH { "role"?, "status"? }   // allow-list only
→ 403 if caller is not admin
→ 409 if removing the last admin

Backend stores

  • users.role (user | admin). Enough for learning; move to a roles table only if you need permissions.
  • users.status: pending | active | disabled
  • audit_log: event, user_id, actor_id, ip, user_agent, metadata jsonb, created_at

Security

  • Check role on every admin route server-side; FE guard is UX only.
  • Mass assignment: PATCH accepts only role/status. Can't set email_verified, password_hash, etc.
  • Disable user → revoke all sessions immediately.
  • Audit log is append-only (no UPDATE/DELETE grants for the app role).
  • Pagination with a max page size.
