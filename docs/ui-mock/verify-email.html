Feature

API

POST/api/auth/verify-email
POST/api/auth/verify-email/resend
verify  { "email", "code" }
→ 200 verified
→ 400 { code: "OTP_INVALID" }   // wrong OR expired, same message
→ 429 too many attempts

resend  { "email" }
→ 202 always (no enumeration)

Backend stores

  • email_otps.code_hash (HMAC-SHA256 with a server key, not plain)
  • attempts += 1 on each wrong code; max 5, then the code is dead
  • consumed_at set on success (single use)
  • New code invalidates older codes for the same purpose
  • users.email_verified_at, status → active
  • audit_log: email.verified, otp.failed

Security

  • 6 digits = 1M combinations, so the attempt cap + 10-min expiry is what protects it.
  • Resend cooldown 60 s per email, plus a per-IP limit.
  • Compare codes in constant time.
  • FE keeps the email in router state only, not storage.
